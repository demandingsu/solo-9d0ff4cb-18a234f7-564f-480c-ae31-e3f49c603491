# 招标延期核对助手

采购代理人核对招标延期时，需要找回原公告与后续更正公告。本工具输入招标公告**列表页地址**，
沿同站点“下一页”自动抓取详情页，按字段标签读取项目编号、公告类型、发布时间、投标截止时间，
按**项目编号归并**、按**发布时间先后**处理，并在浏览器展示每个项目的当前结果与全部公告链接。

同时核验各公告详情页中的**招标文件附件**：读取附件链接与公告标注的 SHA-256，
下载实际文件计算摘要并逐项比对，避免投标人按错误文件编标。

## 处理规则

| 情形 | 处理结果 |
| --- | --- |
| 更正/延期公告**明确写出新的投标截止时间** | 用新时间**替换**旧时间，状态为“有效” |
| 较晚公告**声明延期却未给出新时间** | 状态标为 **“待核实”**，不再显示/沿用旧截止时间 |
| 所有公告均未公布截止时间 | 状态为“未公布” |
| 只有原始招标公告 | 沿用原截止时间，状态为“有效” |

同一项目的全部公告（原公告、更正、延期）按发布时间升序保留，并附原文链接，便于回溯核对。

## 附件核验规则

页面在“招标文件附件核验（SHA-256）”区域逐项展示附件结果及公告来源：

| 情形 | 结果 |
| --- | --- |
| 实际文件 SHA-256 与公告标注一致（且所有标注一致） | **一致** |
| 实际文件摘要与公告标注不符 | **不一致** |
| 同一附件 URL 在不同公告标注了**不同**摘要 | **标注冲突**，逐条保留各公告标注，不任选一条认定通过 |
| 下载失败、超过 5 MiB 上限、公告未标注摘要 | **无法核验** |
| 目录/详情采集不完整（列表页或详情页抓取失败、达到上限、跨站停止跟随） | 整次核验**不得宣称全部附件通过** |

- 一次核验中**相同 URL 只下载一次**，但每条公告的标注值分别保留并展示来源；
- 每个附件最多读取 **5 MiB**；先看 `Content-Length`，读取过程中再按字节累计兜底；
- 附件链接与标注摘要按“链接所在行/段落/相邻单元格”配对，兼容 `li`、`tr`、`td`、`dl/dt/dd` 等结构；
- 只有**采集完整、无抓取错误且每个附件都一致**时，页面才显示“全部一致”的通过提示。

## 用 Docker Compose 启动

```bash
docker compose up --build
```

- 网页应用：<http://localhost:8000>
- 示例站点（宿主机直连）：<http://localhost:8080>

在网页输入框中填入示例站点的列表页地址（容器内服务名地址，网页后端可直接抓取）：

```
http://example-site/list/page_1.html
```

点击“开始核对”后，页面展示：

1. 抓取概况：遍历的列表页（即“下一页”路径）、公告数、跳过链接、错误信息、采集是否完整；
2. 各项目当前核对结果：项目编号、名称、状态徽章、**当前**投标截止时间；
3. 每个项目可展开的公告历史：公告类型、是否声明延期、发布时间、原文截止时间及链接；
4. 招标文件附件核验：每个附件的文件名/地址、核验结果、实际 SHA-256 与大小，
   以及**每条公告各自标注的摘要与公告来源链接**（同一 URL 只下载一次）。

> 公告链接默认指向容器内网地址（如 `http://example-site/...`），宿主机浏览器无法直接打开，
> 因此页面链接统一经过网页后端的 `/view` 代理打开；示例站点本身也映射在 8080 端口可直接浏览。

### 附件核验场景

| 附件 | 覆盖情形 | 预期结果 |
| --- | --- | --- |
| `CG-2026-001-tender.pdf`（被两条公告引用） | 同 URL、相同摘要 | **一致**；只下载一次，保留 2 条公告来源 |
| `CG-2026-002-tender.zip` | 标注摘要与实际文件不符 | **不一致** |
| `CG-2026-003-tender.pdf`（被两条公告引用） | 同 URL 标注不同摘要 | **标注冲突**；两条标注分别保留，不任选一条 |
| `CG-2026-004-missing.pdf` | 目标文件不存在 | **无法核验**（下载失败） |
| `CG-2026-006-archive.zip` | 文件约 5.5 MiB | **无法核验**（超过 5 MiB 上限） |
| `CG-2026-005-drawings.zip` | 公告未写摘要 | **无法核验**（缺少标注） |
| `CG-2026-004-clarification.pdf` | 标注与实际相符 | **一致** |

示例站点整体含不一致/冲突/无法核验项，因此页面会明确提示**不能宣称全部附件通过**；
正常情况下采集完整且全部一致时，才显示通过提示。

## 解析器的字段适配

详情页解析不绑定固定模板，按“字段标签 → 值”依次尝试：

1. 表格行（`th/td`，含一行两对字段）；
2. `dl/dt/dd` 定义列表；
3. `label` + 输入控件（`input/textarea/select`）；
4. 正文中的“标签：值”段落。

标签支持常见别名（如“招标项目编号/项目编码”“投标文件递交截止时间/开标时间”等），
标签缺失时再用正则兜底；识别不到项目编号的页面会被跳过并记入“跳过链接”。

## 安全与边界

- 仅跟随与入口**同站点**（协议+主机+端口一致）的“下一页”和详情链接，跨站链接跳过并记录；
- 只允许 `http(s)`，拒绝 `file://` 等协议；
- 上限：列表页 10 个、详情页 100 个、单请求超时 15 秒、每个附件最多读取 5 MiB；
- 达到列表页/详情页上限、任一列表页或详情页抓取失败、跨站停止跟随，均记为“采集不完整”，
  附件核验不会宣称全部通过；
- `/view`、`/asset` 代理同样只转发 `http(s)` 目标。
